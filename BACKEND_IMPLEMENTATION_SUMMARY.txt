SECURITY ARCHITECTURE OVERVIEW
================================================================================

AUTHENTICATION
──────────────
1. User logs in via Keycloak (LDAP-integrated)
2. Keycloak issues JWT token containing:
   - username (preferred_username)
   - email
   - issued timestamp
   - expiration timestamp
3. User sends JWT in Authorization header: "Bearer <token>"
4. JwtAuthenticationFilter:
   - Extracts JWT from header
   - Validates signature against Keycloak public key
   - Loads User entity from database
   - Creates Spring Security Authentication
   - Sets SecurityContext

AUTHORIZATION
───────────────
1. PermissionAuthorizationFilter receives request
2. Gets current user from SecurityContext
3. Loads database entry for user
4. Queries all user roles (WHERE deleted_at IS NULL)
5. For each role, loads all permissions (UNION result)
6. Matches request endpoint + HTTP method to permissions
7. If match found:
   - Check if requires_owner_check = TRUE
   - If yes: validate created_by == current_user
   - ALLOW request
8. If no match OR owner check fails:
   - Return 403 Forbidden (JSON response)

PERMISSION RESOLUTION
──────────────────────
Algorithm: Union-Based (Most Permissive Wins)

User: Ahmed (ROLES: SAISIE + VALIDATEUR)
  
  SAISIE role permissions:
    - PARTNER_CREATE
    - PARTNER_LIST_ALL
    - PARTNER_VIEW_OWN (requires_owner_check=TRUE)
    - PARTNER_UPDATE_OWN (requires_owner_check=TRUE)
    - TRANSFER_CREATE
    - TRANSFER_VIEW_OWN (requires_owner_check=TRUE)
  
  VALIDATEUR role permissions:
    - PARTNER_VIEW_ALL
    - PARTNER_VALIDATE
    - TRANSFER_VIEW_ALL
    - TRANSFER_VALIDATE
    - REPORT_EXPORT
  
  FINAL PERMISSIONS (UNION):
    [All 11 permissions above]
    - Can create partners (from SAISIE)
    - Can validate partners (from VALIDATEUR)
    - Can validate transfers (from VALIDATEUR)
    - Can only update own partners (SAISIE + owner check)

MULTI-ROLE SUPPORT
═══════════════════

One user CAN have MULTIPLE roles simultaneously.

Example:
  User: Fatima Al-Mansouri
  Username: fatima.almansouri
  Roles:
    1. PROFIL_SAISIE (assigned 2 months ago)
    2. PROFIL_VALIDATEUR (promoted 1 month ago)
    3. PROFIL_CONSULTATION (added for compliance work)
  
  Resulting Permissions: UNION of all three roles
    - Can create partners (SAISIE)
    - Can validate partners (VALIDATEUR)
    - Can view all partners and print (CONSULTATION)
    - Plus all other permissions from those roles

Benefits:
  - Users can have different roles for different contexts
  - Flexible permission assignment
  - No need to create new roles for combinations
  - Easy to adjust permissions by adding/removing roles

SOFT-DELETE BEHAVIOR
================================================================================

When a record is deleted (User, Role, Permission):

BEFORE:
  Database record visible in queries
  deleted_at = NULL
  deleted_by = NULL

AFTER (Soft-Delete):
  Record still in database but marked as deleted
  deleted_at = 2026-03-31 14:35:22
  deleted_by = 'admin@company.com'
  All queries filter: WHERE deleted_at IS NULL

Benefits:
  ✓ Audit trail: Complete history preserved
  ✓ Compliance: Banking regulations require soft-delete
  ✓ Recovery: Can restore if needed (set deleted_at = NULL)
  ✓ Traceability: Know who deleted what and when

Cascading Soft-Delete:
  When user is soft-deleted:
    - All user_roles are soft-deleted (role assignments revoked)
    - User cannot log in (deleted WHERE clause)
    - Audit trail preserved for all role assignments
